# workspace — чек и локальный каталог

`app` — отдельный модуль с командой, `catalog` — модуль с ценой чая.
Исходники обоих уже есть. В `app/go.mod` указан логический путь каталога,
но опубликованной версии нет. Использовать сеть не нужно.

Из `workspace/app` выполните:

```shell
go run .
go list -m all
```

Первая команда может сообщить об отсутствующей записи `go.sum`, вторая
показывает, что модуль недоступен с `GOPROXY=off`.
Прочитайте сообщение и сформулируйте, чего не хватает: исходников функции,
импорта или способа найти модуль?

## Два способа разработки

1. Свяжите `app` с соседним `catalog` через локальный `replace` в `app/go.mod`.
   Сохраните существующий `require`: замена задаёт источник модуля, а не
   объявляет зависимость. Из `app` команда `go run .` должна напечатать
   `Tea x3: 225`, а `go list -m all` — показать локальный путь замены.
2. Из `workspace/` создайте `go.work`, включающий **оба** модуля. Уберите
   локальный `replace` из `app/go.mod`. Снова запустите приложение из `app`.
3. Измените цену в `catalog` с 75 на 80. Без копирования файлов и без
   изменения импорта добейтесь вывода `Tea x3: 240`.
4. Из `app` сравните `go env GOWORK` и запуск `GOWORK=off go run .`.
   Объясните различие, затем вернитесь к обычному запуску.

Посмотрите `go help mod edit`, `go help work init` и `go help work use`,
если не помните команды. Не объединяйте два модуля в один.

## Проверка результата

```shell
# из workspace/app
go env GOWORK
go list -m all
go run .
go test ./...
# из workspace/catalog
go test ./...
```

Тест приложения проверяет стоимость по текущей цене каталога: цена 80 —
условие последнего шага, а не скрытая константа в тесте.
Останется ли проект работоспособным без вашего `go.work` и `replace`,
когда другой разработчик скачает только `app`?
