# packages — один пакет для двух команд

Сейчас `cmd/receipt` печатает чек и сам вычисляет стоимость. Вторая команда
должна использовать то же правило, без копирования функции.

Из `packages/` запустите исходный проект:

```shell
go run ./cmd/receipt
go test ./...
```

Вывод: `Tea x3: 225`.

`internal` — специальное имя каталога Go: пакет из него может импортировать
только код внутри дерева, корнем которого служит родитель `internal`.
В этой задаче родитель — корень проекта; обе команды находятся в его дереве.

## Что изменить

1. Задайте модулю путь `example.org/workshop/receipt`.
2. Выделите умножение в пакет `internal/pricing` с функцией
   `func Total(unitPrice, quantity int) int`. Оба аргумента неотрицательны,
   произведение помещается в `int`; нулевой аргумент даёт ноль.
3. Сохраните `receiptTotal` в первой команде как тонкий вызов `pricing.Total`:
   существующие тесты и вывод должны сохраниться.
4. Добавьте команду `cmd/quote`, которая использует тот же пакет и печатает
   `Tea x1: 75`. Значения 75 и 1 можно задать прямо в `main`.

Не создавайте второй `go.mod`: обе команды и библиотека — пакеты одного
модуля. В `internal/pricing` должна быть директива `package pricing`,
а в обеих командах — `package main`.

## Проверка

```shell
go list ./...
go run ./cmd/receipt
go run ./cmd/quote
go test ./...
```

`go list` должен показывать три пакета с префиксом
`example.org/workshop/receipt/`. Ответьте: почему путь импорта содержит
`internal/pricing`, а обращаться к функции нужно через `pricing.Total`?
Разрешён ли импорт этого пакета из `cmd/quote`? А из команды другого
модуля с путём `example.org/other`? Объясните по правилу выше.
