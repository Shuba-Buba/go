# tablecases: тариф доставки

Напишите тесты готовой функции `ShippingCost(weight int, express bool) (int, error)`.
Вес задаётся целым числом килограммов, стоимость — целым числом рублей.

Контракт:

| Вес | Обычная доставка |
| --- | --- |
| 1–5 кг включительно | 100 рублей |
| 6–10 кг включительно | 180 рублей |
| 11–20 кг включительно | 300 рублей |

При `express == true` к стоимости прибавляется 150 рублей. Вес меньше 1
или больше 20 недопустим: результат `0, ErrWeight`, независимо от `express`.
`ErrWeight` — объявленная в этом пакете ошибка; её можно проверить через
`errors.Is(err, ErrWeight)`. Текст ошибки не является частью контракта.

В `cases_test.go` создайте таблицу с именами случаев, входом, ожидаемыми
стоимостью и ошибкой. `t.Run(name, func(t *testing.T) { ... })` создаёт
подтест: ошибку легче связать с конкретным случаем. Ошибка должна показывать
вход, полученный и ожидаемый результат. Проверяйте результат и ошибку отдельно.

Сначала выпишите границы допустимого веса и тарифных диапазонов. Включите
обычные и срочные отправления, недопустимый вес и каждый переход между тарифами.
Получите 100% покрытия statements функции. Сам процент не доказывает полноту
контракта: объясните, какое требование проверяет каждая строка таблицы.

```shell
go test -v ./tablecases
go test -coverprofile=coverage.out ./tablecases
go tool cover -func=coverage.out
go tool cover -html=coverage.out
```

`-coverprofile` сохраняет данные покрытия; `go tool cover` показывает долю
исполненных statements по функциям или подсвечивает исходник в браузере.
Сохранение отчёта в `coverage.out` не меняет исходный код функции.

Происхождение: новое упражнение вместо прежнего `tablesum`. Сохранены таблица
и именованные подтесты; добавлены ветви, ошибки и выбор границ. Это подготовка
к домашнему `tabletest`: его парсер и набор случаев вы исследуете самостоятельно.
