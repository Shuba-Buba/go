# testcleanup: файл на время теста

Реализуйте `setupTempFile(t *testing.T, content string) string`:

1. Создайте уникальный временный файл через `os.CreateTemp("", "seminar-*.txt")`.
   `CreateTemp` из стандартного пакета `os` возвращает открытый `*os.File`
   и ошибку; пустой первый аргумент выбирает системный временный каталог.
2. Зарегистрируйте через `t.Cleanup(func() { ... })` удаление файла.
3. Запишите `content` методом `WriteString`, закройте файл методом `Close`
   и верните путь из `Name`. При возврате файл уже закрыт, но ещё существует.

Содержимое записывается буквально, включая пустую строку и Unicode. Каждый
вызов возвращает независимый файл. При ошибках создания, записи или закрытия
используйте `t.Fatal`/`t.Fatalf`. Если файл уже создан, освободите его и при
ошибке записи. Ошибку удаления сообщите через `t.Errorf`; отсутствие уже
удалённого файла допустимо. Пометьте функцию `t.Helper()`.

Cleanup выполняется после завершения теста **и всех его подтестов**.
Cleanup-функции одного теста вызываются в обратном порядке регистрации.
Регистрация должна происходить сразу после получения ресурса: дальнейшая
проверка может завершить тест через `Fatal`. Обычный `defer` helper-функции
выполнится при возврате из helper и удалит файл слишком рано.

Тест `TestFileLifecycle` вызывает helper внутри `t.Run`, читает файл там,
а после возврата из `t.Run` проверяет удаление. Подтест здесь последовательный:
его `Run` возвращается после завершения подтеста и его cleanup.

```shell
go test -v ./testcleanup
```

Происхождение: адаптация прежнего `testcleanup`. Сохранена проверка времени
жизни через подтест; контракт явно включает close и обработку ошибок.
Это строительный блок домашнего `fileleak`: семинар создаёт и удаляет
собственный ресурс, а снимки всех дескрипторов процесса и поиск утечек
остаются домашней работой.
