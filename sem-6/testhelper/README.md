# testhelper: проверки и полезная диагностика

Реализуйте две функции:

```go
func assertEqual(t testingT, got, want int)
func assertContains(t testingT, s, substr string)
```

`testingT` — наш минимальный интерфейс с методами `Helper()` и
`Errorf(format string, args ...any)`. Его реализует `*testing.T`, а в тестах
задачи используется fake, записывающий вызовы. Это позволяет проверить
сообщение об ошибке, не заставляя весь проверяющий тест падать.

`assertEqual` сообщает об ошибке, если числа различаются. `assertContains`
сообщает об ошибке, если `s` не содержит `substr`; пустая подстрока содержится
в любой строке. Используйте `strings.Contains` из стандартной библиотеки:
эта функция возвращает `bool` и проверяет наличие подстроки, включая Unicode.

Обе функции:

- вызывают `t.Helper()` при каждом вызове, до проверки; testing исключает
  этот helper из стека, когда показывает место ошибки;
- при несовпадении вызывают `t.Errorf` ровно один раз и возвращаются;
- при совпадении не сообщают об ошибке;
- включают в сообщение оба сравниваемых числа либо строку и искомую подстроку.

`Errorf` помечает тест упавшим и продолжает выполнение. Наш интерфейс не
предоставляет `Fatal` или `FailNow`: раннее завершение здесь не нужно.

Прочитайте fake в `helper_test.go`: `fmt.Sprintf` применяет аргументы
форматирования, а не сохраняет только строку формата. Проверьте не только
факт ошибки, но и то, что по сообщению можно понять вход и ожидание.

```shell
go test -v ./testhelper
```

Происхождение: адаптация прежнего `testhelper`. Исправлена сигнатура условия
и проверяется содержимое сообщений. Это мост к домашнему `testequal`:
семинар сравнивает только int и ищет подстроку; сравнение коллекций и цепочку
Assert/Require вы реализуете дома.
