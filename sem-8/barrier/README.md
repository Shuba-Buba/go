# barrier — дополнительное упражнение

Реализуйте циклический барьер на `sync.Mutex` и `sync.Cond`. Группа путников
идёт по маршруту: на каждой контрольной точке все ждут друг друга.

```go
type Barrier interface {
    Wait() // прийти на очередную точку и дождаться остальных
    Done() // окончательно сойти с маршрута
}
func New(n int) Barrier
```

`n > 0` — начальное число участников. Текущий раунд завершается, когда
все оставшиеся участники вызвали `Wait`; после этого начинается следующий.
`Done` уменьшает число участников текущего и будущих раундов. Если после
уменьшения все оставшиеся уже пришли, ожидающих нужно немедленно выпустить.

Гарантии вызывающего кода: одному участнику соответствует одна горутина;
она вызывает методы последовательно. Участник либо вызывает `Wait` на
следующей точке, либо один раз вызывает `Done` и больше не пользуется
барьером. `Done` может быть вызван и до первого `Wait`. После ухода всех
участников новых вызовов нет. Отмены и повторного добавления участников нет.

Например, двое из трёх уже ждут, а третий вызывает `Done`: оба ожидающих
продолжают путь. На следующей точке достаточно двух вызовов `Wait`.
Одна горутина может быстро дойти до следующей точки, пока другая ещё
выходит из предыдущего ожидания: различайте раунды, а не только число
пришедших. «Все продолжают» означает разрешение продолжать, не гарантию
одновременного выполнения на процессорах.

Нужны отсутствие гонок, корректность многих раундов и ожидание через
`Cond.Wait`, без busy-wait. Новые задачи ДЗ не требуют реализации барьера.
