# Практика синхронизации

Основной маршрут: `mutexcounter` → `oncecache` → `condbuffer`.
`barrier` — дополнительное упражнение после основного занятия.
Нужен Go 1.27.0 или совместимый более новый; внешних зависимостей нет.

Работайте из этого каталога, содержащего `go.mod`:

```shell
go test -count=1 -race -timeout=1m ./mutexcounter
go test -count=1 -race -timeout=1m ./oncecache
go test -count=1 -race -timeout=1m ./condbuffer
# Дополнительно:
go test -count=1 -race -timeout=1m ./barrier
```

Заглушки сначала компилируются, но намеренно не проходят тесты.
Для одного упражнения не нужно решать остальные. Проверка только компиляции:

```shell
go test -run '^$' -timeout=1m ./...
```

Тесты используют стандартные `sync`, каналы и ограничивающие зависание
таймауты. Таймаут не задаёт порядок выполнения горутин. Зелёный `-race`
проверяет выполненные сценарии, а не все возможные обращения к объекту.

Счётчик закрепляет защиту состояния, кэш — единственное вычисление и
публикацию результата, буфер — ожидание условия. Эти приёмы пригодятся
в `keylock`, `dupcall`, `batcher` и `pubsub`, но домашние задачи добавляют
свои контракты: отмену, свежесть данных, несколько ключей и завершение.
