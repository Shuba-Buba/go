# condbuffer

Реализуйте ограниченный FIFO-буфер фиксированной положительной ёмкости:

```go
type Buffer interface {
    Put(x any) // ждёт, пока появится свободное место
    Get() any  // ждёт, пока появится значение
    Len() int  // текущее число элементов
}
func New(capacity int) Buffer
```

- Используйте `sync.Mutex` и `sync.Cond`; активное ожидание запрещено.
- `Put`, `Get` и `Len` безопасны при конкурентных вызовах.
- Значения, включая `nil` и повторы, не теряются и не дублируются.
- Сохраняется порядок постановки в очередь. Для одновременных `Put`
  взаимный порядок заранее не определён.
- `Len` возвращает снимок размера между 0 и capacity; размер может
  измениться сразу после возврата. Разные буферы независимы.
- Вызывающий код передаёт `capacity > 0`. Закрытие и отмена в API не входят;
  пользователь обеспечивает нужное количество производителей и потребителей.

Создайте условную переменную `cond := sync.NewCond(&mu)`, где `mu` —
тот mutex, который защищает состояние буфера. Перед ожиданием захватите
mutex и проверьте условие в цикле. `Cond.Wait`
атомарно отпускает mutex и начинает ждать уведомления, затем снова
захватывает mutex перед возвратом. Уведомление само по себе не обещает,
что условие всё ещё истинно: другой участник мог изменить буфер первым.
После изменения состояния уведомляйте ожидающих нужного условия.

`cond.Signal()` будит одного ожидающего, `cond.Broadcast()` — всех.
Уведомление не накапливается, когда никто не ждёт. Ожидающие проверяют
состояние буфера, а не количество отправленных уведомлений.
