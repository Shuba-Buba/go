# accesslog

Напишите middleware для сервиса. На каждый запрос оно передаёт ID
обработчику и после его возврата делает одну запись в журнал.

```go
type Entry struct {
    ID     string
    Method string
    Path   string
    Status int
    Bytes  int
}

func Wrap(next http.Handler, log func(Entry)) http.Handler
func RequestID(ctx context.Context) string
```

- Возьмите непустой `X-Request-ID` из запроса или сгенерируйте новый.
  Сгенерированные ID непустые и различаются даже у одновременных запросов
  к одному экземпляру middleware. Конкретный формат не важен.
- Положите ID в контекст передаваемого запроса, сохранив отмену и значения
  исходного контекста. `RequestID` возвращает ID из контекста или пустую
  строку. Исходный запрос менять не нужно.
- Добавьте тот же ID в `X-Request-ID` ответа до вызова `next`.
  Считайте, что `next` не меняет этот заголовок.
- В `Entry` запишите метод, `r.URL.Path` без query string, итоговый статус и
  сумму `n`, возвращённых всеми вызовами `Write`. Передавайте обработчику
  те же `n` и ошибки записи, которые вернул нижележащий writer.
- Побеждает первый `WriteHeader` или первый `Write` (он означает `200 OK`).
  Обработчик, который ничего не записал, тоже считается ответившим `200`,
  но с нулём байтов. Обёртка сохраняет заголовки и тело ответа.

`next` и `log` не равны `nil` и допускают параллельные вызовы. В рамках
задачи обработчики не паникуют и не используют `1xx`, потоковую отправку,
обновление протокола или дополнительные интерфейсы writer.

Подсказка: оберните `http.ResponseWriter` и храните счётчики в экземпляре
обёртки **для одного запроса**. В контексте используйте ключ собственного
неэкспортируемого типа.
