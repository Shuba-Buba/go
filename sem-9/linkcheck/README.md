# linkcheck

Напишите параллельный HTTP-клиент, который проверяет список ссылок:

```go
type Result struct {
    Status int
    Err    error
}

func Check(ctx context.Context, client *http.Client, urls []string, limit int) []Result
```

- Отправьте по одному `HEAD` на каждый элемент `urls`. Одинаковые адреса
  считаются отдельными элементами. Используйте переданный `client`, в том
  числе его настройки перенаправлений.
- Результат той же длины и в том же порядке, что и входной срез. Если
  `client.Do` вернул ответ без ошибки, закройте `Body` и сохраните
  `StatusCode`. Код `404` или `503` — тоже полученный HTTP-ответ
  (`Err == nil`).
- При ошибке запроса верните `Status == 0` и саму ошибку или обёртку,
  которая сохраняет исходную ошибку для `errors.Is`. Ошибка одной ссылки
  не отменяет остальные. Ошибку от `Body.Close` можно игнорировать.
- Одновременно можно обрабатывать до `limit` элементов: слот освобождается
  после закрытия тела или ошибки запроса. Если работы достаточно,
  используйте все слоты. Число рабочих горутин должно зависеть от
  `limit`, а не от длины списка.
- Привяжите все запросы к `ctx`. Если к моменту взятия элемента контекст уже
  отменён, не отправляйте запрос и запишите `ctx.Err()` для этого элемента.
  Дождитесь завершения запущенных операций перед возвратом. Уже полученные
  HTTP-ответы остаются в результате даже после отмены.

На входе `client != nil`, `ctx != nil`, `limit > 0` и корректные
абсолютные HTTP(S) URL. Для пустого входа верните результат длины 0.

Подсказка: раздавайте работникам **индексы**, чтобы каждый заполнял свой
элемент. `http.NewRequestWithContext` связывает запрос с отменой. Закрывайте
тело внутри обработки одного элемента, а не при выходе всей горутины.
